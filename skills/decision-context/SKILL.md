# Decision Context

확정된 결정을 출발점으로 별도 `context-reader` 서브에이전트가 관련 문서만 읽게 한다. 메인 에이전트는 짧은 보고서를 종합해 구현에 필요한 제약과 검증 조건만 유지한다.

## 먼저 확인

이 스킬은 orbit이 설치된 저장소에서만 쓴다. 저장소 루트에 `.claude/orbit-manifest.json`이 없으면 "이 저장소에는 orbit이 설치되어 있지 않습니다(`/orbit:setup`으로 설치)"라고 알리고 멈춘다. 문서 폴더 이름은 그 파일의 `docsDir` 값이다(이하 `<docs>`, 보통 `<slug>-docs`).

## 입력 확인

1. `$ARGUMENTS`와 현재 요청에서 ADR 번호 또는 `<docs>/decisions/` 경로와 수행할 작업을 찾는다.
2. ADR이 명시되지 않았으면 `<docs>/decisions/README.md` 인덱스만 읽어 적용할 후보를 찾는다.
3. 후보가 없거나 여러 개면 추정하지 말고 사용자에게 어떤 ADR을 적용할지 묻는다.
4. 사용자가 요청하지 않은 탐색 깊이·문서 수·글자 수 확장은 하지 않는다.

직접 호출 예:

```text
/orbit:decision-context D01 위키 링크 검사 훅 구현
```

## 맥락 수집

적용할 ADR마다 `context-reader` 서브에이전트를 별도 호출한다. 위임 메시지는 다음 형식을 사용한다.

```text
ADR: 순번 ID 또는 D-슬러그-YYMMDD-HHMMSS 또는 <docs>/decisions/<파일명>.md
작업: 이번에 구현하거나 검토할 구체적인 작업
범위 조정: 사용자가 명시한 경우에만 적는다
```

- 메인 에이전트의 대화 전문이나 조사 과정을 위임 메시지에 넣지 않는다.
- `context-reader`가 끝날 때까지 구현을 시작하지 않는다.
- 동일 ADR을 같은 작업에서 중복 호출하지 않는다.
- 세 개가 넘는 ADR이 동시에 필요하면 먼저 상위 결정이나 작업 범위를 좁힌다.

## 판정 처리

각 보고서 마지막 판정에 따라 처리한다.

| 판정 | 처리 |
|---|---|
| `구현 가능` | 보고서를 종합한다. |
| `질문 해결 후 구현` | 구현을 멈추고 필요한 질문만 사용자에게 제시한다. |
| `링크 오류 수정 후 재실행` | 문서 경로와 오류를 알리고 맥락 수집을 다시 실행하기 전에는 구현하지 않는다. |

서로 다른 ADR의 제약이 충돌하면 최신 번호를 자동으로 우선하지 않는다. 대체 관계가 명시되어 있는지 확인하고, 명확하지 않으면 사용자 판단을 요청한다.

## 구현용 맥락 압축

보고서를 다음 형식으로 한 번만 합친다. 문서별 요약이나 긴 인용은 옮기지 않는다.

```markdown
## 적용 결정

- ADR과 현재 작업에 적용되는 결정

## 반드시 지킬 제약

- 구현이 위반하면 안 되는 규칙

## 구현 영향

- 변경할 동작·파일·산출물에 미치는 영향

## 하지 않을 범위

- ADR이 제외했거나 이번 작업에 포함되지 않는 내용

## 검증 조건

- 구현이 결정을 따랐음을 확인할 조건

## 남은 질문

- 없으면 `없음`
```

이 압축본만 구현 계획과 작업 에이전트 위임에 사용한다. 원문 위키 전체, 제외된 문서, 서브에이전트의 작업 과정은 전달하지 않는다. 구현용 맥락을 새 파일로 저장하지 않는다. 사용자가 기록을 요청했을 때만 해당 결정을 ADR이나 위키에 반영한다.

## 구현 전 확인

다음을 모두 만족할 때만 구현을 시작한다.

- 적용할 ADR이 확정되었다.
- 모든 보고서 판정이 `구현 가능`이다.
- 결정 사이의 충돌이 없다.
- 남은 질문이 구현 결과를 바꾸지 않는다.
- 검증 조건을 실행 가능한 형태로 설명할 수 있다.

# 위키 노트 스키마와 갱신 기준

> `{{DOCS_DIR}}/wiki/` 아래의 지식 노트에 적용한다. `_`로 시작하는 운영 문서와 템플릿은 필요한 항목만 사용해도 된다.

## 파일 이름

- 짧고 내용을 바로 알 수 있는 이름을 쓴다.
- `.md`를 뺀 파일 이름이 볼트 안의 다른 연결 대상과 겹치지 않게 한다.
- `#`, `|`, `^`, `:`, `%%`, `[[`, `]]`는 파일 이름에 쓰지 않는다.
- 같은 대상을 다른 이름으로 부를 때는 파일을 복제하지 않고 `aliases`에 추가한다.

## 필수 속성

노트 맨 위에 다음 YAML 속성을 둔다.

```yaml
---
title: "노트 제목"
aliases: []
type: concept
status: draft
summary: "이 노트가 무엇을 설명하는지 한 문장으로 쓴다."
created: 2026-07-30
updated: 2026-07-30
sources: []
related: []
---
```

### `type`

| 값 | 용도 |
|---|---|
| `concept` | 개념, 원칙, 용어 |
| `system` | 검토하거나 적용하는 AI 시스템·도구 |
| `experiment` | 가설, 방법, 결과가 있는 실험 |
| `reference` | 논문, 공식 문서, 외부 사례 같은 원자료 정리 |
| `guide` | 반복해서 사용할 절차와 구현 지식 |

새 종류가 반복해서 필요해지기 전에는 값을 늘리지 않는다.

### `status`

| 값 | 뜻 |
|---|---|
| `draft` | 작성 중이거나 근거 확인이 덜 됨 |
| `active` | 현재 사용할 수 있는 지식 |
| `superseded` | 더 새 노트나 지식으로 대체됨 |
| `archived` | 현재 쓰지 않지만 기록으로 보존함 |

### 나머지 속성

- `title`: 본문 첫 제목과 같게 쓴다.
- `aliases`: 다른 이름과 약어를 문자열 목록으로 쓴다.
- `summary`: 맥락을 고를 때 사용할 한 문장 요약이다.
- `created`: 처음 만든 날짜다. 이후 바꾸지 않는다.
- `updated`: 의미 있는 내용을 바꾼 날짜다.
- `sources`: 원문 URL이나 출처 노트 링크를 넣는다.
- `related`: 직접 관련된 문서만 위키 링크로 넣는다. YAML 안의 링크는 `"[[wiki/문서]]"`처럼 따옴표로 감싼다.

## 본문 구조

모든 노트는 다음 세 부분을 기본으로 한다.

```markdown
# 노트 제목

## 핵심

이 노트에서 다시 사용할 내용을 짧게 설명한다.

## 세부 내용

근거, 비교, 적용 범위와 한계를 적는다.

## 근거와 판단

- 확인: 원자료에서 직접 확인한 내용
- 주장: 출처가 주장하지만 우리가 따로 검증하지 않은 내용
- 추정: 여러 근거를 바탕으로 우리가 추정한 내용
```

실험 노트는 `질문`, `가설`, `방법`, `결과`, `해석`을 추가한다. 절차 노트는 `입력`, `순서`, `통과 조건`을 추가한다.

## 연결 규칙

- 볼트 루트인 `{{DOCS_DIR}}/`를 기준으로 연결한다. 예: `[[wiki/세션-맥락]]`, `[[decisions/D01-example]]`.
- 문장에 맞는 표시가 필요하면 `[[wiki/에이전트-하네스|AI 하네스]]` 형식을 쓴다.
- 같은 문서로 이어지는 모든 언급을 연결하지 않는다. 첫 번째 의미 있는 언급과 관계를 설명하는 곳에 연결한다.
- 존재하지 않는 문서를 링크만으로 미리 만들지 않는다.
- 코드 블록, URL, 파일 경로 안의 단어는 자동 연결 대상에서 제외한다.
- `related`는 주요 관계의 기계 판독용 목록이다. 본문의 링크는 문맥을 설명하는 용도로 함께 사용할 수 있다.

## 검사 명령

```bash
# 전체 문서의 스키마, 깨진 링크, 중복 이름, 미연결 언급 검사
npm run wiki:check

# 한 문서에서 확실한 미연결 언급만 자동 연결한 뒤 다시 검사
npm run wiki:fix -- {{DOCS_DIR}}/wiki/문서.md
```

자동 수정은 기존 노트의 고유한 제목이나 별칭과 정확히 일치할 때만 수행한다. 의미가 불확실하거나 같은 이름의 후보가 여러 개면 파일을 바꾸지 않고 진단을 출력한다.

## 갱신 기준

### 새 노트를 만든다

- 다른 작업에서도 다시 쓸 지식이다.
- 기존 노트 하나에 자연스럽게 합칠 수 없다.
- 출처나 판단 근거를 설명할 수 있다.

### 기존 노트를 갱신한다

- 같은 대상에 새 사실이나 실험 결과가 생겼다.
- 기존 설명의 범위나 한계가 바뀌었다.
- 더 정확한 출처나 연결 문서를 찾았다.

### 합치거나 대체한다

- 두 노트가 같은 대상을 설명하면 하나로 합친다.
- 이전 지식이 더는 유효하지 않으면 `superseded`로 바꾸고 새 노트를 `related`에 연결한다.
- 과거 기록으로만 남길 노트는 `archived`로 바꾼다.

노트를 삭제하기 전에는 다른 문서가 연결하고 있는지 확인한다. 확정된 결정은 위키에서 바꾸지 않고 ADR 규칙에 따라 새 결정으로 대체한다.
